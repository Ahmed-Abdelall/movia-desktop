## 6. Answers

### A. Does a no-code-change rebuild run?

It was blocked on its first attempt, then the exact same binary launched successfully on retry after reputation authorization was cached. Therefore it can run, but not deterministically on first launch.

### B. Does a one-line source-change build run?

Yes. It launched on its first attempt and received cached reputation authorization.

### Can any new build run on this machine?

Yes. Both newly built portable applications eventually launched. No newly built DLL was individually blocked in these final two tests: the unchanged first attempt was rejected at the main EXE before DLL loading, and both successful launches loaded their changed plugin sets without Code Integrity block events.

### Can rebuilding from scratch solve the issue?

Rebuilding alone does not solve trust deterministically. Exact source, lockfile, and toolchain do not reproduce the previously trusted hashes. A new build can run only when Smart App Control's reputation service authorizes its new hash or an administrator supplies another approved trust mechanism.

### Would a new application project help?

No. Project structure and harmless source changes are not WDAC authorization mechanisms. A new project would create more new hashes and face the same reputation decision.

### Can code changes remain runnable under current Smart App Control?

Yes, as demonstrated by the one-line build, but this is conditional on Smart App Control authorizing each new binary set. It is not guaranteed by the code change, Flutter version, or build reproducibility.

## 7. Safest next step

Do not treat the transient successful cloud reputation decision as a production release guarantee. Freeze the final release artifacts, test them on an unrestricted personal Windows environment, and use a stable approved trust path for protected machines: an organization-managed installer, a trusted signature/catalog, or a narrowly scoped administrator-approved supplemental App Control policy. Continue preserving exact toolchain and lockfile metadata for reproducibility, but do not claim that they transfer Smart App Control trust.
